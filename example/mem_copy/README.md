# **Memory Copy Example**

This example demonstrates a memory copy operation using the IRON framework to transfer data through the NPU (Neural Processing Unit) and enables a way to help analyze performance characteristics. The design uses AIE (AI Engine) cores with ObjectFIFOs for data movement.

---

## **Files**

- **mem_copy.py**: IRON Python design that generates the AIE configuration for memory copy operations
- **mem_copy.cpp**: C++ host application that executes the memory copy on the NPU and validates results
- **mem_copy_golden.py**: Generates golden reference data for validation
- **CMakeLists.txt**: Build configuration for generating XCLBINs and test executables

---

## **Design Overview**

The `mem_copy.py` design creates a parameterized memory copy implementation that:

- Uses multiple AIE cores in parallel to maximize throughput
- Employs ObjectFIFOs for efficient data movement between host memory and AIE cores
- Supports configurable number of cores, channels, and tile sizes
- Handles workloads that may not divide evenly across cores using partial tile processing
- Uses runtime barriers to synchronize workers with the runtime sequence
- Implements task groups for parallel drain operations to maximize memory bandwidth

### **Key Features**

- **Data Type**: Uses `bfloat16` for transfers
- **Configurable Parameters**:
  - Number of cores (up to 16 for NPU1, 32 for NPU2)
  - Number of DMA channels per column (1 or 2)
  - Tile size (elements per tile, default 1024)
  - Transfer length (total elements to copy)
- **Operation Modes**:
  - **Compute Mode** (bypass=False): Data passes through AIE cores using the `passThroughLine` kernel from `mem_copy.o`
  - **Bypass Mode** (bypass=True): DMA-only path that forwards data through MemTiles without AIE core computation, useful for measuring raw memory bandwidth
- **Kernel**: Uses `passThroughLine` kernel from `mem_copy.o` when in compute mode

## **Building and Running**

The design is built using CMake. The build system generates:

1. **XCLBIN files**: NPU configuration for specific core/channel/tile combinations
2. **Instruction sequences**: Runtime instructions for specific transfer lengths
3. **Host executable**: C++ application to run the design

### **Command Line Arguments**

The Python design (`mem_copy.py`) accepts:
- `-d, --dev`: Device type (`npu` or `npu2`)
- `-l, --length`: Transfer size in elements
- `-c, --cores`: Number of cores to use
- `-ch, --channels`: Number of channels (1 or 2)
- `-b, --bypass`: Use DMA-only bypass path (true/false, yes/no, t/f, 1/0)
- `-ts, --tile-size`: Tile size in elements (default: 1024)
- `-t, --trace-size`: Trace buffer size
- `-o, --output-file-path`: Output path for generated MLIR

The C++ host application (`mem_copy.cpp`) accepts:
- `-x, --xclbin`: Path to XCLBIN file
- `-k, --kernel`: Kernel name
- `-i, --instr`: Path to instruction file
- `-l, --length`: Transfer length in elements
- `--ref`: Path to golden reference file
- `-v, --verbosity`: Output verbosity level

---

## **Performance Metrics**

The host application measures and reports:
- **Latency**: Execution time in microseconds
- **Bandwidth**: Effective bandwidth in GB/s (calculated from input + output data movement)

---

## **Validation**

The design validates correctness by:
1. Comparing output against golden reference data generated by `mem_copy_golden.py`
2. Checking for buffer overruns by padding the output buffer and verifying padding remains zero
3. Reporting mismatches with detailed error information
